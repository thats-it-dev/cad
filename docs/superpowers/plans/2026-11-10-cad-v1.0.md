# cad v1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.0 of `cad.thatsit.app` — one body, pencil sketches on the iPad, extrude and cut through an OpenCascade WASM kernel, STEP export, projects on the device.

**Architecture:** A feature-history document in pure TypeScript is serialised into one deterministic `cascade-core` script per rebuild; the script runs in a module worker and returns triangle meshes whose `face_index`/`edge_index` carry topology identity. A three.js canvas holds the solid and a 2D canvas on top of it holds the ink, so the pen draws into the model without touching the UI. Kit shell provides the two collapsible panels.

**Tech Stack:** Vite 8 + TypeScript 5.9 strict + Lit 3 (from `https://kit.thatsit.app`), three.js (bundled), `cascade-core` 2.0.6 (vendored client + `public/kernel/` assets), Playwright + Vitest, IndexedDB.

**Spec:** `docs/superpowers/specs/2026-11-10-cad-design.md` (this repo) becomes `docs/spec.md` in `~/workspace/apps/cad` — the contract the tests are written against. This plan is copied to `~/workspace/apps/cad/docs/superpowers/plans/` in Task 1 so the checkboxes live with the code they track.

## Global Constraints

- Values are stored as **integer micrometres**; millimetre floats exist only at the kernel boundary (`MM_PER_UM = 0.001`). STEP is written in millimetres because `saveShapeSTEP` takes no unit parameter.
- Kernel is **`cascade-core` 2.0.6** (OCCT 8.0). `guiState` is always `{ "Cache?": false }`. Nothing may depend on the kernel's internal `argCache`.
- `public/_headers` CSP must be `default-src 'self'; script-src 'self' 'unsafe-eval' 'wasm-unsafe-eval' https://kit.thatsit.app; … worker-src 'self' blob:; connect-src 'self' blob: https://kit.thatsit.app` — and nothing broader.
- The kernel assets (`cascade-worker.js`, `cascadestudio.wasm` 20.25 MiB, `fonts/*.ttf`) live in `public/kernel/` and must never appear in the service worker precache list.
- `src/**/*.ts` stays under 400 lines (guardrail); `npm run verify` (typecheck, unit, knip, e2e) is green before every commit; e2e never downloads the 21 MB kernel — `?kernel=fake` swaps in a stub worker, and exactly one longer-timeout test uses the real kernel.
- e2e may not call `waitForTimeout`; wait on a condition with `expect(...).toPass()` or a locator assertion.
- One body per document in v1.0. Fillet, chamfer, measurement and multi-body are v1.1+ and must not be built early.
- App name is `cad`, at `https://cad.thatsit.app` (from the spec's title); re-check with Michael before `new`.

## Review Focus

These are the failure modes the spec implies that no single task's happy-path tests would catch. Each line gets a test in the named task.

1. **Pen and finger in the same gesture** (`pointerdown` pen → `pointerdown` touch → `pointermove` pen) — expected: the stroke keeps drawing and the camera does not move. Owned by Task 8, e2e with `Input.pointerrawdown`-style multi-pointer sequences.
2. **A kernel operation that fails** (zero-depth extrude, a non-planar face as a sketch host) — expected: the last good solid stays on screen and the step is flagged. `evaluate()` still returns a mesh after a throwing script, so "empty mesh" must read as failure, not as an empty part. Owned by Task 9.
3. **Two changes before the first rebuild finishes** — expected: exactly one rebuild of the newer document lands, and the canvas never shows geometry from a discarded document. Owned by Task 6 (coalescing) and pinned end-to-end in Task 9 with a slow stub worker.
4. **Reopening a document whose step kind is unknown** (written by a later version) — expected: the stored JSON is not rewritten, the step shows as broken. Owned by Task 2 (`normalize`).
5. **Units reaching the printer** — expected: a 40×30×12 mm box exports a STEP whose length unit is MILLIMETRE and whose volume reads 14400 mm³, not 1.44e13. Owned by Task 5, and re-checked in the real-kernel e2e.

### Task 3: Sketch geometry — strokes to entities

**Files:**
- Create: `src/sketch/frame.ts`, `src/sketch/entities.ts`
- Test: `test/sketch.test.ts`

**Interfaces:**
- Consumes: `Umm`, `mm`, `um`, `Sketch`, `Entity`, `PlaneRef` from Task 2.
- Produces:
  - `type Vec3 = [number, number, number]`, `type Frame2 = { origin: Vec3; u: Vec3; v: Vec3; normal: Vec3 }` (millimetres)
  - `frameFor(plane: PlaneRef, origin: Vec3, axes: [[Umm,Umm,Umm],[Umm,Umm,Umm]]): Frame2`
  - `frameFromNormal(point: Vec3, normal: Vec3): Frame2` — `u = normalize(cross(n, |n.z| < 0.9 ? [0,0,1] : [1,0,0]))`, `v = cross(n, u)`
  - `project(p: Vec3, f: Frame2): [number, number]`, `unproject(p2: [number, number], f: Frame2): Vec3`
  - `type RawStroke = { points: [number, number][] }` (screen px)
  - `type Map2 = { originPx: [number, number]; mmPerPx: number }` — the one place the px→plane-mm scale lives; uniform and positive, no y sign here (the camera's flip is applied by the view layer, Task 8, which produces the `Map2`)
  - `toEntities(strokes: RawStroke[], opts: { map: Map2; snapUmm: Umm; closed: boolean }): Entity[]` — plane = `[(px-originPx[0])*mmPerPx, (py-originPx[1])*mmPerPx]`, then simplify with a **stroke-relative** tolerance, then snap, then merge duplicate consecutive points. It applies **no** 3D frame; that is the script builder's job (Task 5)
  - `const CORNER_EPSILON_UM: Umm = 25` — a floor, not the tolerance. The tolerance is `max(CORNER_EPSILON_UM, extent × 0.01)` with `extent` = the stroke's bounding-box diagonal in µm. An absolute epsilon cannot work (pencil jitter is 0.1–1 mm), and deriving it from the snap grid would delete genuine small steps from a printed part.
  - Simplify by **turn angle**, never by chord deviation: cut at each vertex whose turn from the previous segment exceeds `atan2(cornerTolUmm, meanSegmentLength)` (≈4.5° at 1%), collapse each nearly-straight run to its two endpoints, then snap, then merge consecutive duplicates. Chord deviation (RDP) is wrong for this input: a rectangle corner sits exactly on the chord of its neighbours, so it gets deleted while the wobble survives. Order inside `toEntities`: map px→µm → split+collapse → snap → merge → close (append the start point exactly once when `closed`). `isClosed`'s gap is in plane µm, converted from px by the caller.
  - `isClosed(points: [number, number][], gapPx: number): boolean`, `snapSegment(a: [Umm,Umm], b: [Umm,Umm], snapUmm: Umm): [Umm,Umm]` — snaps to multiples of `snapUmm` and to horizontal/vertical
  - `areaOf(entity: Entity): number` (mm², 0 for an open poly)

- [x] **Step 1: failing tests for the plane math.** Round trip within 1e-9: `unproject(project(p, f), f)` for a frame from `frameFromNormal([0,0,12], [0.2,-0.4,1])`. `frameFor({kind:"axis",axis:"XZ",offset:5_000}, …)` puts the origin at `[0, 5, 0]` mm and the normal at `[0,-1,0]`.
- [ ] **Step 2: failing tests for snapping and closure.** A rectangle drawn as 37 jittered px points becomes one `poly` with 4 points whose µm values are multiples of 1000. A stroke whose start and end are 3 px apart with `closed: true` gains the closing point exactly once (point count grows by 1, not 2). A 200 px wobble stays two segments — no arc fitting in v1.0. Plus the two-knob pair from the Task 3 ruling: on a 40 mm × 20 mm stroke, ±0.3 mm jitter collapses to 4 corners while a genuine 5 mm step survives simplification and then snaps to the grid; and with `Map2 = {originPx:[0,0], mmPerPx:1}` the output equals the input numbers snapped, so the transform provably does nothing at identity.
- [ ] **Step 3: implement** the two files, with the `Map2` signature above (`scaleY`/`origin` in the original brief was a plan defect — see the ledger ruling).
- [ ] **Step 4:** unit tests PASS; `npm run typecheck`.
